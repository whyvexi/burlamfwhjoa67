# Selesta

Личный Telegram-бот для eskalane (Дани). Python 3.12–3.14, aiogram 3,
PlusVibe API, SQLite. Текстовый помощник с профилем и памятью: пишет код,
помогает с архитектурой, автоматизацией и монтажом. Ищет в интернете и читает
публичные страницы по ссылкам. Выполнение кода, изображения и голос не подключены.

## Запуск на macOS / Linux

```bash
cd "/Users/irinastebleva/Desktop/selesta agent"
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` вставь токен бота из [@BotFather](https://t.me/BotFather) и свой ключ PlusVibe:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
LLM_API_KEY=твой_api_ключ
OWNER_TELEGRAM_ID=твой_числовой_telegram_id
LLM_BASE_URL=https://plusvibeapi.ru/v1
LLM_MODEL=deepseek/deepseek-v4-flash-0731
```

```bash
python -m selesta
```

Если не знаешь свой ID, оставь `OWNER_TELEGRAM_ID` пустым, запусти бота и отправь
ему `/id` в личке. Впиши число в `.env`, останови процесс Ctrl+C и запусти снова.
Без OWNER_TELEGRAM_ID бот отвечает только на `/id`; вызовы LLM запрещены.
Ключи вставляются локально: присылать их в чат не нужно.

На Ubuntu используй установленный Python 3.12+ вместо `python3.14` и свой путь
к проекту. Бот работает, пока запущен процесс и компьютер не спит.
Запускай только один экземпляр на один Telegram-токен.

## Профиль и память

Все предоставленные предпочтения включены в `profile.md`. Файл перечитывается
при каждом запросе, поэтому правки профиля не требуют перезапуска.

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Справка |
| `/id` | Числовой Telegram ID |
| `/profile` | Базовый профиль |
| `/remember текст` | Постоянная заметка (до 30 заметок по 1000 символов) |
| `/memory` | Список заметок с ID |
| `/forget 3` | Удаление заметки № 3 |
| `/reset` | Удаление истории, профиль и заметки остаются |
| `/status` | Модель и лимиты контекста |
| `/search запрос` | Явный поиск в интернете |
| `/read https://example.com` | Явное чтение страницы |

## Интернет

Поиск работает через DuckDuckGo с библиотекой [DDGS](https://pypi.org/project/ddgs/),
без дополнительного API-ключа. Обычный вопрос вроде «найди актуальную документацию
aiogram» позволяет модели самой вызвать поиск, затем прочитать нужные страницы.
Команды `/search` и `/read` запускают указанный инструмент до обращения к модели.

Примеры:

```text
Найди в интернете документацию aiogram по обработке callback_query
Прочитай https://docs.python.org/3/library/asyncio.html и выдели полезное для бота
/search Premiere Pro proxy workflow Apple Silicon
/read https://docs.aiogram.dev/en/latest/
```

Инструменты подключены через [function calling PlusVibe](https://plusvibeapi.ru/docs/tool-calling).
Каждый раунд работы с инструментами может требовать нового платного вызова LLM:
до трёх раундов, шести выполнений инструментов и четырёх вызовов модели на ответ.
Веб-данные передаются модели только внутри текущего ответа; в историю сохраняется
финальный ответ со ссылками. Промежуточные страницы отдельно не сохраняются.

Читатель поддерживает HTML и текст без JavaScript и авторизации: до 2 МБ на страницу,
до 14 000 символов извлечённого текста. Если текст обрезан, инструмент сообщает это
модели. PDF, закрытые страницы и сайты с CAPTCHA могут быть недоступны.
DuckDuckGo может временно ограничивать запросы; в этом случае можно дать прямую ссылку.

Загрузка разрешена только по HTTP(S) на стандартных портах. Локальные/служебные IP,
включая адреса из DNS и перенаправлений, блокируются. Для сайтов используется отдельная
сессия без LLM-ключа, cookies и системного прокси. Содержимое страниц помечается как
недоверенные данные; системная инструкция запрещает исполнять команды из страниц
и передавать профиль или секреты в поиск. Это текстовые инструменты чтения, не браузер
с доступом к твоим аккаунтам.

Изменения вступают в силу после перезапуска бота. Дополнительных полей `.env` нет.

## Хранение и доставка

Последние 20 успешных пар вопрос–ответ хранятся в `data/selesta.db`.
В запрос передаются целые пары в хронологическом порядке с ограничением истории
по символам. Это приблизительное ограничение объёма, не точный подсчёт токенов.
Профиль и заметки добавляются отдельно к каждому запросу. Старые пары удаляются
из БД. После удаления заметки можно очистить `/reset`, чтобы её текст не остался
в недавнем диалоге. Переписка в самом Telegram этими командами не удаляется.

Ответы отправляются обычным текстом, Markdown-код сохраняется буквально.
Длинные ответы делятся с учётом UTF-16; ответы свыше 12 000 символов приходят
файлом `.md`. Одновременные сообщения обрабатываются последовательно.
Неудачные запросы API не попадают в историю. Автоматических повторных платных
запросов нет; ответ, полученный от API, сохраняется перед отправкой в Telegram.

Профиль, заметки и выбранная история передаются PlusVibe для генерации.
`.env` и `data/` исключены из Git. Для переноса памяти скопируй `data/`
при остановленном боте. В группах бот не отвечает; профиль доступен только владельцу.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Тесты работают без токенов: проверяют API через HTTP-моки, ограничения доступа,
память, порядок истории, разбиение текста, цикл инструментов, его лимиты,
валидацию ссылок, DNS, перенаправления и извлечение HTML. Настоящее подключение проверяется
после заполнения `.env`: `/start`, затем обычное текстовое сообщение.
Ошибка 404 может означать, что указанный идентификатор модели недоступен на аккаунте.

Используются [Chat Completions PlusVibe](https://plusvibeapi.ru/)
и [long polling aiogram](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html).
