# Загрузка Selesta на Bothost

## Настройки бота

1. Загрузи содержимое архива `selesta-bothost.zip` в корень проекта.
   В корне должны оказаться `main.py`, `Dockerfile`, `requirements.txt`, `profile.md`
   и папка `selesta/`. Не помещай весь проект в дополнительную вложенную папку.
2. Платформа: **Telegram**, библиотека: **aiogram 3**, если доступен такой выбор.
3. В дополнительных настройках укажи главный файл **`main.py`**.
4. Включи **«Использовать собственный Dockerfile»**. В нём закреплён Python 3.12,
   установка зависимостей из wheels и команда `python main.py`.
5. Добавь переменные окружения и выполни **новый деплой / пересборку**.
   Простого рестарта старого контейнера недостаточно.

Не указывай `selesta/bot.py` или `selesta/__main__.py` как главный файл:
они используют относительные импорты пакета. Корневой `main.py` запускает пакет правильно.
Локальная команда `python -m selesta` тоже продолжает работать.

## Переменные окружения

```dotenv
LLM_API_KEY=твой_ключ_PlusVibe
OWNER_TELEGRAM_ID=твой_числовой_Telegram_ID
LLM_BASE_URL=https://plusvibeapi.ru/v1
LLM_MODEL=deepseek/deepseek-v4-flash-0731
```

Токен Telegram укажи в поле **Bot Token** Bothost. Бот принимает его через
`TELEGRAM_BOT_TOKEN`, `BOT_TOKEN` или `API_TOKEN`. Если хостинг не передаёт токен,
добавь `TELEGRAM_BOT_TOKEN` вручную. `LLM_API_KEY` — ключ модели, не Telegram-токен.

`OWNER_TELEGRAM_ID` — именно твой ID в Telegram, а не `USER_ID` аккаунта Bothost.
Если его пока не знаешь, оставь пустым, после запуска отправь `/id` боту,
добавь полученное число и перезапусти контейнер. Без владельца LLM недоступен.

Архив не содержит `.env`, ключей и локальной базы данных. Все ключи задаются в панели.
База автоматически создаётся в `/app/data/selesta.db` — каталоге хранения Bothost.
Перед запуском на хостинге останови локальный экземпляр этого же бота.

## Если сборка снова упала

Открой **лог сборки**, найди первую ошибку `ERROR` и скопируй несколько строк перед ней.
Уведомление «Контейнер не найден» сообщает только об отсутствии результата сборки.
Если сборка прошла, но бот выключается, нужен **лог запуска** — это уже другой этап.

Docker на этом компьютере не установлен, поэтому Docker-образ локально не запускался.
Зависимости проверены через pip resolver для Linux x86_64 / CPython 3.12,
с требованием готовых wheels без компиляции. Это не подтверждает успешный деплой
в аккаунте Bothost: для него нужны загрузка архива и фактический лог сборки.
